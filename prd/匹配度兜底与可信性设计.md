# 匹配度兜底与可信性设计 PRD

> 版本 V1 · 2026-10-11 · 适用范围：匹配引擎（core.js `computeMatch`）与所有对外展示的匹配度数字
> 关联文档：《古题版24题_设计稿V1》

## 一、要解决的问题

匹配度百分比是用户对"准不准"的第一判断依据，存在两类失效风险：

| 失效模式 | 表现 | 用户感知 |
|----------|------|----------|
| 分数虚高 | 人人 95%+ | "随便答答都 95%，骗人的吧" |
| 分数偏低 | 人人 60% 以下 | "我跟谁都不像，不准" |

前者曾是本项目真实发生过的线上事故：旧算法（余弦相似度 + 全正向量）实测所有人物匹配度普遍 99%，算法实质失效，已被替换。

## 二、四层兜底设计

### 第 1 层：算法层——八维标准化 + 曼哈顿距离

- 当前公式：`pct = 100 − 标准化平均绝对差 × 38 + 确定性微扰`
- 曼哈顿距离对"某一维度差异特别大"的惩罚更敏感，天然拉开人物之间的区分度；
- 余弦相似度只看方向不看幅度，是当年"人人 99%"的根因，永久弃用。

### 第 2 层：系数校准（k = 1.6 的来历与复测）

- 校准方法：**蒙特卡洛模拟**——程序随机生成 10,000 个"虚拟用户"（每题随机选一个选项），完整走一遍计分与匹配流程，记录所有匹配度，形成分数分布；
- 验收口径：中位数落在 72–78、95 分位不超过 82，即"普通人 75% 上下、最幸运也不超过 82"，既不虚高也不难看；
- **当前实测（三轮复测，每轮 10,000 次，结果完全稳定）**：

| 轮次 | 中位数 | 95 分位 | min | max |
|------|--------|---------|-----|-----|
| 1 | 75% | 80% | 66 | 85 |
| 2 | 75% | 80% | 66 | 85 |
| 3 | 75% | 80% | 67 | 85 |

- 结论：k=1.6 在古题版 24 题下**无需重调**；README 中的校准数据以本轮实测为准（旧版"74% / 78%"为未经复现的继承数据，已从文档移除）。

### 第 3 层：输出区间硬夹取（最后防线）

- 匹配度强制收敛到 **55–99** 区间：`Math.min(99, Math.max(55, bestPct))`
- 即使出现极端作答（全选同一选项、权重失衡），用户看到的数字也不会跌破 55 或冲上 100；
- 99 不取 100：匹配度本质是"相似度叙事"，100% 意味着"你就是他"，失去趣味悬念。

### 第 4 层：确定性微扰（防同分撞车）

- 微扰来源：所有题目答案序号之和 % 7 − 3（±3 的确定性抖动）；
- 作用：让不同作答序列即使八维总分接近，也能得到略有差异的匹配度，避免大量用户看到一模一样的数字；
- 选"确定性"而非随机数：同一用户重进结果不变，保证可信度。

## 三、与题目改版的联动规则

题库无论怎么改（换题、加题、调权重），以下流程为固定验收项：

1. 跑 3 轮 × 10,000 次随机作答模拟；
2. 中位数与 95 分位落在验收口径内 → 直接上线，不改 k；
3. 超出区间 → 优先微调 k（每次步进 0.1），重复模拟直至达标；
4. 禁止通过"放宽夹取区间"来凑分布——夹取只是最后防线，不是调节手段。

## 四、上线后监控（真实数据回流）

- 埋点建议：记录每次作答的最终匹配度与命中人物 id（仅本地或匿名上报）；
- 预警阈值：真实用户匹配度中位数 < 68 或 > 82，说明真实作答分布与随机模拟显著偏离，需人工复核题库权重；
- 复核工具：重跑模拟脚本（10 行代码，见下）即可对照。



## 六、V2 增补：八维标准化（测量公平性）

### 为什么要加这一层

改版前实测发现两个问题：

1. 题库八维供能极不均（洞察总权重 84、开创仅 24，相差 3.5 倍），导致「开创型」「担当型」人物系统性地难以被命中；
2. 用户可达分数空间与人物基准分向量不匹配，5 万次模拟中**只有 13–15 位人物可被命中，单个人物占比高达 42%**，命中分布熵仅 2.2 bit（均匀上限 4.81 bit）。

### 做法

- **用户侧**：原始分按题库解析推导的均值/标准差归一化——每题独立均匀作答时，某维原始分 = 各题该维权重之和，其期望与方差可逐题精确累加，题库改动自动跟随，**无需人工重调常数**；
- **人物侧**：按当前候选池（女性优先 / 男性优先 / 不限）内的均值/标准差归一化——切池时基准自动重算；
- 两侧都变成 z 分数后再算曼哈顿距离 → **八个维度天然等权**，题目供能多寡不再影响公平性。

### 校准结果（真实引擎 5 万次模拟；另分池各 2 万次）

| 指标 | 改造前 | 改造后 |
|---|---|---|
| 可命中人物数 | 13–15 / 28 | **28 / 28** |
| 最热人物占比 | 42% | **10.5%** |
| 命中分布熵 | 2.2 bit | **4.48 bit**（均匀上限 4.81） |
| 匹配度中位数 | 75% | **76%** |
| 95 分位 | 80% | **85%** |
| 女性池可命中 | 8 / 10 | **10 / 10** |
| 男性池可命中 | — | **18 / 18** |

### 复现口径

- 系数 K = 38：由「标准化平均绝对差中位数 ≈ 0.63 → 目标得分 76%」反推；
- 改题库后**必须重跑本节的模拟**，若中位数跌出 72–80 或命中熵低于 4.2，则按验收流程微调 K 或复核人物基准分。
## 七、复现脚本

```js
// 在 core.js 加载后的控制台或 node 中执行（需 localStorage 桩）
function sim(){const a=QUESTIONS.map(q=>Math.floor(Math.random()*4));
  const raw={};DIMS.forEach(d=>raw[d]=0);
  QUESTIONS.forEach((q,i)=>{const w=q.o[a[i]][1];for(const k in w)raw[k]+=w[k]});
  const sc={};DIMS.forEach(d=>sc[d]=Math.min(97,Math.max(25,Math.round(32+raw[d]*2.3))));
  let bp=-1;FIGURES.forEach(f=>{let mad=0;
    DIMS.forEach((d,i)=>mad+=Math.abs(sc[d]-f.scores[i]));mad/=8;
    const pct=Math.round(100-mad*1.6);if(pct>bp)bp=pct});return bp}
const arr=[];for(let i=0;i<10000;i++)arr.push(sim());
arr.sort((a,b)=>a-b);
console.log('中位数',arr[5000],'95分位',arr[9500],'min',arr[0],'max',arr[9999]);
```
